## Review fixes 2026-09-22
- MAJOR fixed: switching back to a cached kit no longer depends on onPlayable re-firing. `bankReady`
  is idempotent (a second call for the bank audio already has only flushes the pending send);
  onComplete/onFallback call it whenever `id == instrument && bankInstrument != id`, and
  `changeInstrument` calls it directly when the bank is already cached. Test
  `t12_2_switchBackToACachedKitReportedOnlyByOnCompleteDoesNotHang` (`CachedCompleteOnlyKits` fake).
- Switch order is now pause → setBank → setPerformance → setRoom (§2.6 step 5). When the bank is
  ready before the compile, the room design is deferred to `send()` (`roomAfterSend`); a failed
  compile still sends it. T12.2 asserts setRoom after setPerformance and none between bank and perf.
- `intendedPlaying` (set by send(autoPlay), toggle, end of playlist, sync-off with no return) drives
  wasPlaying, toggle and the playback hints; the clock is used only for position.
- End of the last item saves the resume point at songUs = 0; toggle() on an ended Performance
  seeks 0 before play().
- Instrument switch during the sync test re-requests SYNC_CLICK with the new profile (startUs −1
  once the click is current, autoPlay kept).
- DEVIATION (kept): the next item is pre-compiled only when its instrument equals the current one.
  A Performance compiled with another profile would be discarded by the switch anyway (the switch
  clears `precompiled` and recompiles for the new bank), so pre-compiling it only costs HKLoader
  time during playback; a cross-instrument next item compiles on demand like any request.
- Wiring note: one owner for setListener (`session.start()`), re-set explicitly after every
  stopEngine/startEngine cycle.
- LevelProbe takes a `preLimiterPeak` tap and refuses to run without it unless
  `allowPostLimiter = true` (harness test only); new test `probeRefusesToMeasureWithoutAPreLimiterTap`.

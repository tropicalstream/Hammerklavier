# WP12 wiring: SessionController into AppController

WP12 is pure (`core/.../session/`). Nothing in `Wiring.kt` constructs it; `AppController` owns one.

## Wiring.kt
No change. SessionController uses the existing fields: `audio`, `kits`, `library`, `compiler`,
`designer`, `scenes`, `settings`, `loader`, `post`.

## AppController
1. Add a forwarding `RenderControl` (the GlHost is attached after construction and can detach):
   `private val renderFwd = object : RenderControl { /* each method: gl?.method(args) */ }`.
   On `attach(gl, overlay)` replay the last instrument/view/quality into the new host
   (SessionController also re-sends them on its next change).
2. Construct once, after `w`:
   ```kotlin
   val session = SessionController(w.audio, renderFwd, w.kits, w.library, w.compiler, w.designer,
       w.scenes, w.settings, w.loader, w.post, nowMs = { SystemClock.elapsedRealtime() })
   ```
   then set the hooks: `onUiEvent = { e -> w.ui.onEvent(e); refreshOverlay() }`,
   `onBrightnessCap = { c -> onBrightness?.invoke(c) }`, `onLeave = { onLeave?.invoke() }`,
   `onRotateToken = { companion.rotateToken() }`, `statusPriority = UiText::priority` (WP10; keep the
   default until WP10 merges), `version = BuildConfig.VERSION_NAME`, and `companionUrl` /
   `companionToken` when the CompanionServer starts.
3. The listener has ONE owner, `session.start()`, which calls `audio.setListener(this)`; AppController
   never calls `setListener(session)` before it. `startEngine()`: after `w.audio.start()`, call
   `session.start()` on the first start only; on every later start (after a `stopEngine()`), call
   `w.audio.setListener(session)` again, because `stopEngine()` does `w.audio.setListener(null)` and the
   listener must be re-set after every stopEngine/startEngine cycle.
4. Delete the direct stub driving: `applyAll`'s `else -> "deferred"` branch becomes
   `session.onAction(a)` for every UiAction the controller does not handle itself (Back/overlay
   focus stays in AppController). Media buttons: `session.toggle()/next()/previous()`.
5. CONTROL (`DebugControl`): `play` -> `session.controlPlay(name, instrument)`, `seek` ->
   `session.controlSeekDisplayMs(ms)`, `instrument` -> `session.instrument(id)`, `view` ->
   `session.view(v, framing)`, `rescan` -> `session.importsChanged()`.
6. Companion: pass `session` as the `CompanionCommands` (replaces the object at line ~241).
7. `applyQuality(level)` -> `session.onThermalLevel(level)` (it applies the QualityLadder, the Q3
   rest and the brightness cap); keep `gl?.setQuality` only in `attach`.
8. A 1 Hz main-thread tick (reuse the overlay refresh Runnable): `session.tick()`; the overlay
   facts come from `session.facts()` (delete the local minimal-facts function, line ~252).
   Also update `session.batteryTenths` / `debugLine` before each tick.
9. `onStop(displayInteractive)` and the Leave path: `session.onAppLeft()` (saves the resume point);
   `session.isPlaying()` replaces local playing state for MediaButtons.

## Smoke steps (stubs everywhere else still fine)
1. Launch: log shows the library loaded and the title card; `adb shell am broadcast ... --es play <id>`
   -> NullAudio receives setBank, then setPerformance with generation 1.
2. `--es instrument HARPSICHORD` while playing -> pause(30), setBank, setPerformance(startUs=-1), one setRoom.
3. `--es view HALL` -> exactly one setRoom logged.
4. `--el seek 10000` -> position reads 0:10 in the overlay.
5. Leave and relaunch -> resume title shown in the facts; Recently played lists the work.
6. Companion `GET /now` returns the JSON with display-time position updating at 1 Hz.

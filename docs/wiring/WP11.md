# WP11 wiring (wp11-assets)

WP11 ships data and Python tools only: no Kotlin class replaces a stub. What changes for WP0 is which
assets exist and which stubs can now be pointed at them.

## Swap
- Nothing in `Wiring.kt` is WP11's. The real data is consumed by other WPs' classes when they are wired:
  - `Wiring.kits` (WP4 `audio.KitManager`): kit directories `assets/instruments/grand/` (kit `grand-hd`,
    HARD, 18 units, 572 regions), `assets/instruments/upright/` (kit `upright`, XFADE, 5 units, 166 regions),
    `assets/instruments/harpsichord/` (HARD, 3 units, 108 regions), `assets/instruments/stub/` (unchanged).
    The directory is the **instrument** id (`grand`, `upright`, `harpsichord`, `stub`), not the `kit` field:
    only one grand kit ships (samples-hd approved; `grand-std` is not built).
  - `Wiring.library` (WP9 `LibraryServiceImpl`, or `StubLibrary` meanwhile): `assets/catalog.json`
    (schema 1: 67 works, 197 movements, 11 shelves, 6 sources, 12 Start-here movements; Handel HWV 430,
    Rameau La Poule and Couperin are absent and are left out automatically).
  - Credits panel (WP10): `assets/credits.txt`; licence texts and `assets/licenses/SOURCES.csv`.
- Until WP4 lands, `StubKits` keeps using the stub bank; nothing breaks if the new kit directories are
  present and unused.

## Hook-ups
- Build: `app/build.gradle.kts` already has `noCompress += listOf("opus", "bin", "json", "mid", …)`; keep it
  (the kit loader memory-maps/streams the Opus units and env.bin).
- Git: the kit `.opus` and `env.bin` files are committed through Git LFS (the existing
  `app/src/main/assets/instruments/**/*.opus|*.bin` lines). A clone needs `git lfs pull` before building,
  or the APK carries pointer files and every kit fails its SHA-1 check.
- `core/src/test/resources/wp11/real/` (7 WAV test regions + `regions.json`, 2.6 MB) is **not committed**:
  it waits for the LFS line in `docs/requests/WP11.md` item 2. Regenerate with
  `python3 tools/pipeline/export_test_regions.py` (needs `tools/cache/samples`).
- CI (`tools/ci.sh`): `python3 -m unittest discover tools/pipeline/tests` (61 tests, ≈ 25 s),
  `tools/pipeline/check_ledger.py`, `tools/pipeline/size_report.py` (prints a MIDI-over-budget warning,
  exit 0).
- No Settings keys, permissions or manifest changes.

## Smoke
1. `git lfs pull && git lfs ls-files | grep instruments/` lists 26 kit files (18 + 5 + 3 opus, 3 env.bin) plus the
   stub's 4.
2. `python3 tools/pipeline/check_ledger.py` → `ledger: 253 rows, ok`; `python3 tools/pipeline/size_report.py`
   → `... cap 100000000 (samples-hd): OK`.
3. `python3 -m unittest discover tools/pipeline/tests` → `OK` (T11.3 validates every kit in assets).
4. `tools/gw :core:test` green (WP1's `MidiCorpusTest` reads `midi_facts_golden.json`, now 210 files).
5. `tools/gw :app:assembleRelease`; `unzip -l app/build/outputs/apk/release/*.apk | grep -c 'assets/midi/'`
   ≥ 210 and the APK is ≤ 100 MB (≈ 82 MB expected).
6. On the glasses (integrator, after WP4 is wired): select each instrument; the log shows the kit's
   `map.json` sha1 prefix as the PCM cache file name (`96fbecb7` grand, `02353628` upright, `52c53549`
   harpsichord) and the prefetch completes; play Start-here 1 (BWV 846, grand) and 2 (Invention 1,
   harpsichord).
